## 実装メモ

### 補正の数理 — なぜこの形にしたか

`energyForProfile()` は `total = (力行 − 回生 + 空調W×時間)` で**2項に対して線形**。そこで:

```
補正後kWh = kDrive × (力行kWh − 回生kWh) + kAux × 空調kWh
```

この形の効き目が大きいのは、**再計算に標高プロファイルが要らない**こと。
力行・回生・電費の3つのスカラーがあれば空調項は逆算でき(空調 = 電費×距離 − (力行−回生))、
あとは掛け算だけ。おかげで一覧46行でもマップでも即座に効き、
要件§3.2「重い計算はバッチ、画面は表示だけ」を崩さずに全画面へ適用できた。

`packages/core/src/calibration.ts` を新設した。**`correction.ts` には入れていない** —
あちらはDEMのトンネル補正で、`correctedIdx` / `correctedM` がD1の列・診断書の開示・
ゴールデンテストに繋がっている。同じ「補正」でも別物なので、名前空間を分けた。

### 空調を分離できないことがある(これは仕様)

走行も空調も「走った分だけ」増えるので、**同じ路線・同じ季節のデータだけでは
2つの係数を数学的に切り分けられない**(2つの説明変数が比例して解が一意に決まらない)。

- 分離できる条件: 夏と冬の両方の行がある(空調Wが 3000/8000 と変わる)か、運行時間の列がある
- 分離できないときは `kAux` を1に固定して `kDrive` だけを当て、`separable: false` を返す
- 画面には「このデータでは空調の分離ができないため、総合効率の1係数として補正しました」と出す

判定は相関係数(> 0.999)と行数(< 4行)で行う。係数は 0.30〜3.00 で頭打ちにし、
頭打ちになったら画面で警告する(列の対応づけや単位の取り違えがそこで分かる)。

### ディーゼル(L)は実燃費だけを当てる

企画書の実証データはトラック運送会社のデジタコ = 軽油の記録なので、L も受ける。
ただし**軽油の消費から車両効率は出さない**。そのためにはエンジンの熱効率を仮定する必要があり、
その仮定がそのまま係数に化けて意味を失うため。L のときは実燃費 km/L だけを補正し、
ディーゼル比較(F-2-6)とTCOの燃料費が実力値になる。画面にもそう書いた。

### CSVをサーバーに送らないことの担保

- `apps/web/app/calibrate/_components/` と `lib/` に **`fetch` / `use server` / `FormData` /
  `sendBeacon` / `XMLHttpRequest` が1件も無い**ことを確認済み(`page.tsx` の `@/lib/data` は
  路線一覧を**読む**だけで、CSVはそこに渡らない)
- クライアント側の import は `@regen/core` / 共通UI / フォーマッタのみ
- 列の対応づけを画面でやる方式にしたので、**デジタコの形式が未知のままでも実装を進められた**。
  実データが届いて読めなければ `csv.ts` の `HINTS` に列名を足すだけで済む

### 文字コードとファイル

デジタコの書き出しはShift_JISのことが多い。ArrayBufferで読み、UTF-8で復号して置換文字が出たら
`TextDecoder("shift_jis")` で読み直す(Node 22・主要ブラウザとも対応を確認)。BOMは落とす。
5MB / 20,000行を超えるファイルは理由を示して拒否する。

### 適用範囲

| 画面 | 適用 |
|---|---|
| `/` マップ | ○ 判定の色・凡例の集計まで作り直す |
| `/routes` 一覧 | ○ 数値・判定・CSVダウンロード(補正済みの旨を末尾に記録) |
| `/routes/[id]` 診断書 | ○ 結論バッジ・数値タイル・充電計画・ディーゼル比較 |
| `/routes/[id]/compare` 比較 | ○ `SimInput.calib` を渡すだけ |
| **`/s/[id]` 共有シナリオ** | **×(意図的)** 保存時の値を凍結する記録なので、閲覧者の補正で動いてはいけない |

診断書は本体を `_components/DiagnosisSheet.tsx`(Client)に移した。25m配列は渡していない
(補正の再計算にはスカラーだけで足りるため。RSCペイロードを膨らませない)。
**サーバーが返すHTMLは常に無補正**で、localStorageを読んだあとに差し替える
(ハイドレーション不一致を避ける。印刷の初期状態が無補正なのも都合がよい)。
補正中は「仮定」節に係数を出すので、補正済みの紙が前提を隠したまま独り歩きしない。
