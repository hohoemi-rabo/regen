## スコープ

- Better Auth導入(セッションはD1)。**一般利用者側には一切露出させない**

- 認証テーブルがDrizzleスキーマで管理されている
- シークレットがリポジトリに含まれない
- 一般画面のバンドルにBetter Authのクライアントコードが混入しない

## 実装メモ

### 保護は二段。レイアウトの `redirect()` だけでは足りない

最初はレイアウトガードだけで組んだが、`curl -i /admin` が **307ではなく200** を返した。
`redirect()` はストリーミングが始まった後に投げられるため、HTTPとしては
「200 + RSCペイロード内の `NEXT_REDIRECT`」になる。ブラウザは遷移するので実害は無く、
管理画面の中身も出ていなかったが、**受入条件「未認証でアクセスすると弾かれる」を
HTTPの層で満たしていない**ので直した。

- `apps/web/middleware.ts` — Cookieの**有無だけ**を見て 307 / 401 を返す。第一段
- `requireAdmin()` / `requireAdminApi()`(`lib/auth.ts`)— D1を引いてセッションを検証する。**これが実体**

middleware から `getCloudflareContext().env` は呼べない(CLAUDE.md)ので、この二段になる。
`getSessionCookie()` はCookieの中身を検証しないため、middleware だけでは保護にならない。

**保護される範囲はルートグループで決めた。** `app/admin/(protected)/` の下は全部保護される。
パスを見て素通しする書き方にすると、条件を1つ間違えたときに保護が丸ごと外れる。
`/admin/login` と `/admin/setup`(と `/api/admin/setup`)はグループの外・matcherの除外に置いた。

### 公開の登録経路を持たない(要件§11-6)

better-auth は `emailAndPassword` を有効にすると `/sign-up/email` を生やす。
catch-all で**自前で404**にした。ライブラリの `disableSignUp` / `disabledPaths` は
初回登録用の `auth.api.signUpEmail()` まで塞ぐか版依存なので、確実な方を境界にしている。

初回登録は `/api/admin/setup` だけ。**管理者0人 かつ 合い言葉(`ADMIN_SETUP_TOKEN`)一致**の
両方が要り、どちらかを外すと **404**(登録口の存在を教えない)。合い言葉の照合はSHA-256にしてから
比べ、長さの違いでも時間差が出ないようにした。登録が済むと以後は404になる。

### 判定しきい値(F-7-4)— どこまでが「即時」か

`judge()` に第3引数を足し、既定値は要件§5のまま。**ゴールデンテストは1行も変えていない。**

保存すると D1 の `routes.verdict` をその場で計算し直す(46行を読んで `judge()` に通す。
判定の定義をSQLに書き写すと、片方だけ直したときに黙ってずれる)。

反映のされ方は画面で違う。**`revalidatePath` は OpenNext の R2 incremental cache を
purge できなかった**(実測。cache-busting クエリを付けても古いHTMLが返る)ので:

| 画面 | 反映 | やり方 |
|---|---|---|
| `/routes` 一覧 | 即時 | `force-dynamic` にした。D1の46行1クエリなので安い |
| `/` マップ | 即時 | `force-dynamic` + クライアントがしきい値で判定し直す(R2の焼き込みは古いまま) |
| `/routes/[id]` 診断書・比較 | 最大1時間 | 46件を事前生成しているので ISR の窓に従う |

しきい値の画面にこの通り書いてある。過大な約束をしない。

### バッチとの噛み合わせ

- **しきい値を `paramsSnapshot()` に入れた。** 入れないと変えても版が変わらず、
  更新検出の早期リターンで再計算されないまま古い判定が配信され続ける(`PIPELINE_REV` も4に)
- 変化ガードは `verdict` を「重い変化」として扱うので、**しきい値変更後の初回バッチは
  設計どおり止まる**。実測で5路線の反転を検出して停止することを確認した
- **車両マスタの種を `ON CONFLICT DO NOTHING` に変えた。** それまでは毎回全列を上書きしており、
  管理画面で直した値が次の週次バッチで消えていた。編集がバッチ実行後も残ることを実測で確認

### 車両マスタ(F-7-2)

15列すべて編集できる。**物理削除はせず `is_public` の切替**で公開から外す(行は残す)。
検証は `normalizeVehicle()`(packages/core)。認証済みの経路だが、値域の壊れた車両を入れると
比較画面の計算そのものが壊れるので `POST /api/scenarios` と同じだけ検証する。
EVは電池容量、ディーゼルは燃費を必須にした(欠けたまま保存すると比較画面で0除算になる)。

### 375pxで見つけた2つの溢れ

- **バッチの失敗メッセージ**に長いパスが入り、折り返せずに横スクロールが出ていた
  → `break-words` + 1行目120文字で打ち切り
- **版・日時を数値タイル(26px)に置いていた**。タイルは数字のためのもの(DESIGN §5.3)で、
  17文字の版文字列だとグリッドのトラックが広がる → `DefinitionRow` に移した

### 分かっている限界

`/admin/setup` は管理者が既にいると**中身は出ない(フォームを描かない)がHTTPは200**を返す。
`notFound()` も `redirect()` と同じくストリーミング後に投げられるため。
登録を実際に止めているのは `/api/admin/setup` 側で、そちらは404を返す。

### ログアウトは `content-type` が要る(2026-08-30に発覚)

`fetch("/api/auth/sign-out", { method: "POST" })` だけでは better-auth が **415** を返し、
**Cookieが消えないままログアウトしたつもりになる**。ヘッダに `content-type: application/json` と
本文 `{}` を付けること。

**症状の出方が分かりにくい。** Cookieが残ったまま `/admin/login` へ送ると、ログイン画面は
有効なセッションを見つけて `/admin` へ送り返すので、「ログアウトを押すと管理画面に戻る」
という形でしか表に出ない。`fetch` の応答を捨てていたので、失敗しても画面は何も言わなかった。

いまは `res.ok` を確かめ、失敗したら遷移せずその場に文言を出す。遷移も
`router.replace` ではなく `window.location.assign` にした(Cookieを消した直後は
Routerのキャッシュに古い判定が残りうるため)。
