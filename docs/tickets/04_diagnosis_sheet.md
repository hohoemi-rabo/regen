# 04 F-2 路線診断書 (`/routes/[id]`)

ステータス: 完了

原型: `docs/prototype/検証レポート_W1.html`

## スコープ

構成は上から(順序を崩さない — DESIGN §6.2):
結論バッジ → 勾配プロファイル → 数値タイル群 → 充電計画 → ディーゼル比較 → 精度ランク・補正区間の開示 → 試算の仮定 → 出典

- 勾配プロファイルは自前SVG(§5.4)。主要停留所・最高地点の注記、補正区間は破線
- ホバー/タップで距離・標高・勾配のツールチップ(F-2-3)
- 数値タイル: 距離/累積上下/最高最低標高/最急勾配/電費(夏冬)/回生回収量/往復使用率(F-2-4)
- 充電計画: 便数・日次kWh・追加充電回数・時間帯目安(F-2-5。粒度は要件§13-2、まず回数+目安文言で実装)
- ディーゼル比較: 燃料費・CO2(F-2-6)
- 仮定の開示: params.ts の既定値を同一画面に表示(F-2-9)
- 46路線を `generateStaticParams` で全件プリレンダリング(CLAUDE.md方針)
- 印刷: A4縦1枚、ダークタイル反転、地図/ナビ非表示(DESIGN §10)

## データ

`data/seed/` のプロファイルから表示。重い計算はしない(表示のみ)。夏冬の出し分け等で再計算が要る場合のみ packages/core を使う。

## 受入条件

- F-2-1〜F-2-9 を満たす
- スクロールなしで結論バッジ全体が見える
- ヒーロー数値は1画面に1つ(44px)
- 表示1秒以内(要件§5.1)
- SVGに role="img" + aria-label(DESIGN §9)
- @media print でA4縦1枚に収まる

## 実装メモ

- 充電計画は**代表運行日**(GTFS calendar の曜日フラグで数えて最も便数の多い曜日)の実ダイヤで算出する。
  既存の診断値(日次kWh・追加充電回数・判定)はGTFSの全ダイヤ合計便数ベースでゴールデンテストに固定されているため据え置き、
  差がある13路線では画面に両者の違いを明記した(要件§13-2の判断: 時間帯まで踏み込む)。
- CO2は軽油2.58 kg-CO2/L(温対法標準値)、系統電力0.43 kg-CO2/kWh(全国平均相当)。EV側も発電由来を計上する。
- packages/core への追加のみでアルゴリズムは不変(`correctedIdx` の返却、`cruiseSpeedKmh()`、`CO2`、
  `compareDiesel()`、`chargingPlan()`)。ゴールデンテスト47件は通過。
- 印刷は46路線中39路線がA4縦1枚。補正区間が多い/充電回数が多い7路線は2枚になる
  (本文8pxが下限で、これ以上の圧縮は可読性を損なうため許容とした)。
