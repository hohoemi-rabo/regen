## 1. デザイン方針

### 1.1 このプロダクトの性格

Regenは**業務判断のための道具**である。バス事業者が数千万円の車両更新を決め、自治体が計画に載せ、その根拠を補助金申請に添付する。したがってUIの目的は「楽しませること」ではなく、**数字を疑いようのない形で見せること**にある。

同時に、コンテスト作品として審査員に一目で価値が伝わる必要がある。この二つを両立させる方針を次のとおり定める。

### 1.2 5つの原則

**1. 数字が主役、装飾は脇役。** 画面の視覚的重心は常に数値と地図に置く。飾りのイラスト、グラデーション、影の多用はしない。罫線と余白で構造を作る。

**2. 結論を最初に、根拠をその下に。** 診断書は「EV化可能。ただし日中5回の充電が必要」という結論から始める。プロファイル、電費、仮定はその後に続く。スクロールせずに答えが読めること。

**3. 仮定を隠さない。** すべての試算画面に、使った仮定値(車両スペック・単価・空調)を同一画面で表示する。別ページに逃がさない。透明性がこのサービスの信用の源である。

**4. 色は意味だけを運ぶ。** 判定の3色以外に色を使わない。ブランド色として使えるアクセントは1色に限る。色を情報の唯一の担い手にしない(必ずラベルか記号を併記)。

**5. 年齢を問わず読める。ただしシニア特化にはしない。** 文字サイズ拡大機能は設けない。代わりに本文14px以上、数値は大きく、コントラストを確保する。落ち着いた色数の少ない画面にする。

### 1.3 参照する既存資産

見た目の到達点は検証時のプロトタイプで確認済み。実装時はこれらを基準にする。

- `docs/prototype/検証レポート_W1.html` — 診断書(F-2)の原型
- `docs/prototype/南信州EV適性マップ_46路線.html` — マップ(F-1)の原型

## 2. カラートークン

### 2.1 テーマ方針

**ライト基調の単一テーマ**とする。OS連動のダークモードは実装しない。

理由: (a) 業務利用の想定で、印刷して配る使い方が多い、(b) テーマが1つなら色の検証が1回で済み、審査までの時間を機能に回せる、(c) 部分的に**ダークタイル**を使えばコントラストの見せ場は作れる。

### 2.2 基本トークン

CSS変数として`:root`に定義し、Tailwindのテーマにも同じ値を登録する。

| 役割 | トークン名 | 値 | 用途 |
|---|---|---|---|
| ページ地 | `--page` | `#f9f9f7` | body背景 |
| 面 | `--surface` | `#fcfcfb` | カード・表・地図の下地 |
| ダークタイル | `--surface-dark` | `#1a1a19` | 強調ブロック(結論バッジ等)の背景 |
| 主文字 | `--ink-1` | `#0b0b0b` | 見出し・数値 |
| 副文字 | `--ink-2` | `#52514e` | 説明文 |
| 微弱文字 | `--ink-3` | `#898781` | 軸ラベル・注記・出典 |
| ダーク上の文字 | `--ink-on-dark` | `#ffffff` | ダークタイル内 |
| 罫線 | `--border` | `rgba(11,11,11,0.10)` | カード外周 |
| グリッド | `--grid` | `#e1e0d9` | グラフの目盛線 |
| 基準線 | `--baseline` | `#c3c2b7` | グラフの軸・表のヘッダ罫 |

### 2.3 意味色(判定)

判定は**この3色のみ**。他の用途に転用しない。

| 判定 | トークン | 値 | 記号 | 条件 |
|---|---|---|---|---|
| 適 | `--verdict-ok` | `#0ca30c` | ● | 冬季往復電池60%未満 かつ 最急勾配10%未満 |
| 条件付き | `--verdict-cond` | `#fab219` | ▲ | 電池60〜85% または 急勾配あり |
| 要検討 | `--verdict-ng` | `#d03b3b` | ■ | 電池85%以上 |

**アンバー(`#fab219`)は明るい面の上でコントラストが3:1に届かない。** これは意味色として意図的に選んだ結果であり、次の緩和策を必ずセットで実装する(要件§5.4)。

- 記号(●▲■)とテキストラベルを必ず併記する
- 一覧表(F-5)を代替表示として常に提供する
- **文字に使う場合はアンバーではなく`--verdict-cond-text`(`#b45309`)を使う**(表のセル、バッジ内テキスト等)
- 地図の線・凡例マーカーなど図形にのみ`#fab219`を使い、その場合は縁取り(§7.1)を敷く

検証結果: 3色はCVD(色覚多様性)分離ΔE 11.3、通常視ΔE 27.6でいずれも基準を満たす。

### 2.4 アクセント

| 役割 | トークン | 値 |
|---|---|---|
| アクション | `--accent` | `#2a78d6` |
| アクション(押下) | `--accent-strong` | `#1c5cab` |
| アクション(淡) | `--accent-weak` | `#cde2fb` |

リンク・ボタン・選択状態・グラフの主系列に使う**唯一のブランド色**。判定色と役割が競合しないよう、アクセントを判定の意味に使わない。

### 2.5 グラフ用の色

| 用途 | 値 |
|---|---|
| 標高プロファイル(線) | `--accent` `#2a78d6` |
| 標高プロファイル(面) | `#cde2fb`(不透明度45%) |
| 比較・系列2(ディーゼル等) | `#eb6834` |
| 補正区間 | `--ink-3` の破線 |

系列が3つ以上必要になる場面は作らない(2系列比較に留める)。検証結果: 青×橙はCVD分離ΔE 24.7で十分に区別できる。

## 3. タイポグラフィ

### 3.1 書体

```css
font-family: "Inter", "Noto Sans JP", system-ui, -apple-system, "Hiragino Sans",
             "Yu Gothic UI", sans-serif;
```

Interで英数字・数値を、Noto Sans JPで日本語を受ける。**ウェイトは400と600の2段のみ**(500は使わない。中間ウェイトを混ぜると画面が濁る)。

### 3.2 スケール

| 用途 | サイズ | ウェイト | 備考 |
|---|---|---|---|
| ヒーロー数値 | 44px | 600 | 診断書の結論数値(往復電池%など)1画面に1つだけ |
| 数値タイル値 | 26px | 600 | tabular-nums |
| ページ見出し | 22px | 600 | |
| セクション見出し | 15px | 600 | |
| 本文 | 14px | 400 | 最小サイズ。これ以下は使わない |
| 表・補助 | 13px | 400 | |
| 注記・出典 | 11-12px | 400 | `--ink-3` |

### 3.3 数字の扱い

- **表・グラフ軸・比較列は`font-variant-numeric: tabular-nums`**(桁が縦に揃うこと)
- ヒーロー数値と単体の大きな数値は既定のプロポーショナル数字
- 単位は数値より小さく(14px)、`--ink-2`で添える: `59<span>%</span>`
- 3桁区切りを入れる(`772 kWh`, `1,196 m`)
- 小数は用途ごとに桁を固定: 電費2桁(`0.85`)、距離1桁(`36.8`)、標高・電力量0桁

## 4. レイアウト

### 4.1 グリッドと余白

- 最大幅: 通常ページ **900px**。**データ密度の高いページ(一覧F-5・比較F-3)は最大1200px**。
  地図ページは全幅(地図は画面いっぱいに使う)、`/about`は720px(§6.6)
- 余白の基本単位: **4px**。使う値は 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40
- カード内padding: 20px(モバイル16px)
- カード間: 22px
- 角丸: カード12px、タイル10px、ボタン・チップ8px

### 4.2 ブレークポイント

| 名称 | 幅 | 主な変化 |
|---|---|---|
| モバイル | 〜640px | 1カラム。数値タイルは2列。地図は縦60vh、凡例は下部に折返し |
| タブレット | 641〜1024px | 数値タイル3〜4列 |
| デスクトップ | 1025px〜 | 診断書は最大900px中央寄せ。一覧・比較は最大1200px。地図ページのみ全幅 |

375px幅で破綻しないことを全画面の受入条件とする。

### 4.3 影

影は**カードに1種類だけ**: `0 2px 10px rgba(0,0,0,.06)`。ホバーで影を強めない(代わりに罫線を`--accent`にする)。

## 5. コンポーネント仕様

### 5.1 判定チップ

判定を示す最小単位。表のセル、地図のポップアップ、カード見出しで共通に使う。

```
[● 適]  [▲ 条件付き]  [■ 要検討]
```

- 記号 + ラベルの組。**記号だけ・色だけの表示は禁止**
- 文字色は`--verdict-ok` / `--verdict-cond-text` / `--verdict-ng`
- 背景を付ける場合は各色の10%不透明度、角丸8px、padding 2px 8px

### 5.2 結論バッジ(診断書の最上部)

診断書で最初に目に入る要素。**ダークタイル**(`--surface-dark`)を背景にして、この1ブロックだけコントラストを強くする。

```
┌────────────────────────────────────────────┐
│ ● EV化可能 ── 条件付き                      │  ← 判定チップ(白抜き)
│                                            │
│ 59%                                        │  ← ヒーロー数値 44px
│ 冬季1往復でのバッテリー使用率               │  ← 12px --ink-3
│                                            │
│ 1日16便を走らせるには日中5回の充電が必要     │  ← 14px 白
└────────────────────────────────────────────┘
```

ヒーロー数値は**1画面に1つ**。ここでしか44pxを使わない。

### 5.3 数値タイル

```
┌──────────────────┐
│ 累積上り(片道)    │  ← 12px --ink-2
│ 981 m            │  ← 26px 600 tabular-nums
│ 治部坂峠まで登る  │  ← 11px --ink-3(任意)
└──────────────────┘
```

- グリッド: `repeat(auto-fit, minmax(168px, 1fr))`、gap 12px
- 面`--surface`、罫線`--border`、角丸10px、padding 14px 16px
- 補足行は「その数値をどう読むか」を書く。単位の言い換えは書かない

### 5.4 グラフ(標高プロファイル)

- 線: 2px、`--accent`、`stroke-linejoin: round`
- 面: `#cde2fb` 不透明度45%
- グリッド: `--grid` 1px の水平線のみ(垂直グリッドは引かない)
- 軸ラベル: 11px `--ink-3`
- 注記点: 半径4pxの円 + `--surface`の2px縁取り + 11px 600のラベル
- **補正区間は破線**(`stroke-dasharray: 6 4`、`--ink-3`)で区別し、凡例に「トンネル・高架として補正」と明記
- ホバー: 縦のクロスヘア(`--baseline` 1px)+ 追従する点 + ツールチップ
- ツールチップ: 面`--surface`、罫線`--border`、角丸6px、12px、影あり

### 5.5 表

- ヘッダ: 13px 600 `--ink-2`、下罫`--baseline` 1px
- 行: 下罫`--grid` 1px。**ゼブラストライプは使わない**
- 数値列は右寄せ + tabular-nums
- 横スクロールは表を包むコンテナに`overflow-x: auto`。**ページ本体を横スクロールさせない**
- 行ホバー: 背景`rgba(42,120,214,0.04)`

### 5.6 ボタン

| 種別 | 背景 | 文字 | 用途 |
|---|---|---|---|
| Primary | `--accent` | 白 | 主要動作(保存・共有・CSV) |
| Secondary | `--surface` + 罫線`--border` | `--ink-1` | 副次動作 |
| Ghost | なし | `--accent` | リンク的動作 |

高さ40px(モバイル44px)、角丸8px、14px 600。無効時は`--ink-3`。

### 5.7 フィルタ行

地図・一覧の上部に**1行**で置く(F-1-5)。事業者・判定・精度ランクの3つのセレクト。選択中は`--accent-weak`背景。「絞り込み解除」を右端に置く。

**フィルタで件数が変わっても、残った路線の色は変えない。** 色は判定に紐づくものであり、順位や相対値で塗り替えない。

### 5.8 スライダー(F-3車両比較・F-4実測補正)

ネイティブの`<input type="range">`に`accent-color: --accent`を当てる。**自前のドラッグ実装はしない**
(キーボード操作・スクリーンリーダー・タッチが標準実装のまま得られる)。

- 上段に1行: 左に項目名(13px `--ink-2`)、右に**現在値**(14px 600 `tabular-nums` + 単位は`--ink-2`)
- 下段に最小値・最大値(11px `--ink-3`)。目盛りは刻まない
- トラック高さ4px、つまみ16px。高さは行全体で44px以上を確保する(タッチ目標)
- **値は必ず画面に見えていること**(F-3受入条件「変更中の仮定値がすべて画面に見えている」)
- 既定値から動かした項目は現在値を`--accent`にして、どこを触ったか分かるようにする

### 5.9 数値入力(車両価格・補助金など)

- 高さ40px(モバイル44px)、角丸8px、面`--surface`、罫線`--border`
- **右寄せ + `tabular-nums`**。単位はフィールドの外に`--ink-2`で添える
- フォーカスリングはグローバルの`:focus-visible`(2px `--accent`)に任せ、個別に上書きしない
- 金額は3桁区切りで表示する。空欄は0として扱い、負値は受け付けない

### 5.10 折れ線比較グラフ(TCO)

§5.4の標高グラフと同じ描画作法(自前SVG・固定viewBox・`role="img"`+文章の`aria-label`)に従う。

- **系列は2本だけ。** 車両A=`--accent`、車両B=`#eb6834`(§2.5)。3系列は作らない
- 線2px、`stroke-linejoin: round`。面は塗らない(2系列が重なるため)
- グリッドは`--grid`の**水平線のみ**。横軸ラベル(年)・縦軸ラベル(累計コスト)は11px `--ink-3`
- **交点(損益分岐)には注記を必ず置く**: 半径4pxの円 + `--surface`の2px縁取り + 11px 600のラベル
- 期間内に交点がない場合はグラフ内に注記せず、本文で「◯年以内には分岐しません」と書く
- 凡例は車両名をそのまま使い、色だけに頼らせない(系列名を線の右端か凡例チップに置く)

## 6. 画面設計

### 6.1 `/` マップ(F-1)

```
┌─ ヘッダ(48px) ─────────────────────────────┐
│ Regen        [路線一覧] [このサービスについて] │
├────────────────────────────────────────────┤
│ [事業者▾] [判定▾] [精度▾]          解除     │  ← フィルタ1行
├────────────────────────────────────────────┤
│                                            │
│              地図(全幅・残り高さ)            │
│                                            │
│   ┌── 凡例(左下・浮動) ──┐                  │
│   │ ● 適 34              │                  │
│   │ ▲ 条件付き 12        │                  │
│   │ ■ 要検討 0           │                  │
│   └──────────────────────┘                  │
└────────────────────────────────────────────┘
```

- 初期表示は南信州全域にfitBounds
- 線をクリック → ポップアップ(路線名・事業者・km・便数・往復電池%・追加充電回数・「診断書を見る」)
- モバイルはポップアップを下部シートにする

### 6.2 `/routes/[id]` 診断書(F-2)

上から: **結論バッジ(ダークタイル)** → 勾配プロファイル → 数値タイル群 → 充電計画 → ディーゼル比較 → 精度ランクと補正区間の開示 → 試算の仮定 → 出典。

「結論 → 根拠 → 前提」の順を崩さない。スクロールなしで結論バッジ全体が見えること。

### 6.3 `/routes` 一覧(F-5)

フィルタ行 + 表 + CSVダウンロードボタン。判定列は判定チップ。既定は日次kWhの降順。

### 6.4 `/routes/[id]/compare` 比較(F-3)

左右2カラム(モバイルは縦積み)。上部に共通のパラメータスライダー群、下に車両A/Bの結果。**差分は数値で示す**(「▼ 1,400円/日 安い」)。TCOグラフは横軸に年、縦軸に累計コスト、交点に損益分岐年数を注記。

### 6.5 `/calibrate` 実測補正(F-4)

CSVドロップゾーン。**「データは端末内でのみ処理され、送信されません」を枠内に常時表示**。読み込み後は補正前/後の誤差を並べて表示。

### 6.6 `/about`(チケット11)

長文ページ。最大幅720px、行間1.85。図はプロトタイプのスクリーンショットを使う。

---

### 6.7 `/s/[id]` 共有シナリオ(F-6)

比較(F-3)で作った条件の**記録**。補助金申請や社内説明にそのまま添付できることが目的なので、
**読み取り専用**にする。スライダー・入力欄・車種セレクタは置かない(いじれると「添付した時の条件」が
曖昧になる)。条件を変えたい人は比較画面を開き直す。

- 最大幅**900px**(通常ページ幅。比較の1200pxは操作のための例外幅なので踏襲しない)
- 上から: 見出し(路線名)+ 保存日時・シナリオID・診断データ版 → **この条件での結論**
  (損益分岐年数と1日あたりの差)→ 車両A/Bの結果 → TCOグラフ → 試算の仮定 → 車両スペックの出典。
  §1.2 原則2「結論を最初に、根拠をその下に」を崩さない
- 車両A/Bは**`.grid` を使わず flex で並べる**。印刷CSSの `.grid` は5列固定なので紙で崩れる(§10)
- **A4縦1枚**(§10)。仮定リストは印刷時に1段落へ畳む
- 保存時の車両スペックをそのまま表示する。「後から数値が変わらない」ことを画面で明言する

### 6.8 `/admin/*` 管理画面(F-7)

**運用者が1人で使う裏方の画面。** 公開画面と同じトークン・同じ部品で組み、管理画面専用の色や
装飾を作らない(見た目を分ける必要が無く、分けると二重管理になる)。

- 最大幅**900px**(通常ページ幅)。ヘッダ・フッタは公開画面と共通のものをそのまま使う
- レイアウトの直下に**管理画面のナビ1行**(ダッシュボード / 車両マスタ / 判定しきい値)
- 上から: いま困っていること(期限切れ・失敗した実行)→ 現状 → 操作。
  §1.2 原則2「結論を最初に、根拠をその下に」は管理画面でも同じ
- **一般利用者向けの導線を置かない。** 公開画面から `/admin` へのリンクを張らない(F-7-1)

**警告の出し方**

- フィード期限・バッチ失敗は §5.1 の意味色を**転用しない**。判定の3色は路線の判定専用
  (§2.3)なので、警告は `--verdict-cond-text` の文字 + 罫線カードで表す
- 「あと何日で切れるか」を必ず数字で書く。日付だけを出さない

**フォーム(§5.6 ボタン / §5.9 数値入力に従う)**

- 1画面1フォーム。保存ボタンは右下ではなく**フォーム末尾の左**に置く(読み順のまま到達する)
- **破壊的な操作にも赤を使わない。** 公開停止は Secondary ボタン + 確認文で表す
- 検証エラーはフィールドの直下に11px `--verdict-cond-text` で出し、色だけに頼らない
  (`aria-invalid` と文言をセットで付ける)
- 空欄と0を区別する項目(ディーゼルの電池容量など)は、空欄のまま保存できるようにする

**判定しきい値の画面(F-7-4)**

- 変更は46路線の判定に及ぶので、**保存前に「何路線の判定が変わるか」を出す**
- 既定値(電池60%/85%・勾配10%)からの差は §5.8 と同じく `--accent` で示す
- 「次のバッチ実行では変更の承認が要る」ことを画面に書く(変化ガードで止まるため)


## 7. 地図スタイル

### 7.1 路線ポリライン

```
casing(下敷き): 白 5px 不透明度55%
line(本体):     判定色 2.6px
```

白の縁取りを敷くことで、アンバーの線が明るい地図の上でも視認できる(§2.3の緩和策)。選択中は本体5px。

### 7.2 ベースマップ

国土地理院の淡色地図タイルを使用(出典表記必須)。**彩度を落として表示**し、路線の色が地図に埋もれないようにする。ラベル密度は最小限に。

### 7.3 出典表記

地図の右下に常時: `地理院タイル / GTFSデータリポジトリ`。フッターにも全出典を記載(要件§5.5)。

## 8. モーション

控えめに。業務ツールとして「待たされている感」を出さない。

- ホバー・選択: 120ms ease-out
- ポップアップ・シート出現: 180ms ease-out
- 地図のfitBounds: 400ms
- **数値のカウントアップ演出はしない**(数字は静かに正確に出す)
- `prefers-reduced-motion: reduce` を尊重し、その場合は遷移を0msにする

---

## 9. アクセシビリティ

- 判定は色 + 記号 + ラベルの3重で伝える(§5.1)
- 本文14px以上、`--ink-2`まではコントラスト比4.5:1以上を確保
- アンバーは文字色に使わない(`--verdict-cond-text`を使う)
- 地図のポリラインにはキーボードで到達できないため、**同じ情報に到達できる一覧表(F-5)を必ず提供する**
- SVGグラフに`role="img"`と`aria-label`(路線の概要を文章で)
- フォーカスリング: `--accent` 2px、`outline-offset: 2px`。消さない

---

## 10. 印刷

診断書(F-2)と共有シナリオ(F-6)は**A4縦1枚に収める**。補助金申請や社内説明にそのまま添付できることが要件(F-6-4)。

- `@media print`: ダークタイルは白地+黒枠に反転、地図とナビゲーションは非表示
- グラフは残す(線は黒、面は薄いグレー)。**2系列グラフの系列2は破線グレー**にして白黒で区別できるようにする
- 出典・生成日時・仮定値は必ず印刷に含める
- ページ背景色は白

## 11. 実装上の申し合わせ

- 色は**必ずCSS変数経由**で使う。コンポーネントに生のhexを書かない
- Tailwindの`tailwind.config.ts`にトークンを登録し、`text-verdict-ok`のように使う
- 影・角丸・余白もトークン化された値のみ使う(任意の数値を書かない)
- **Tailwind v4に上げない**(v3.4.17固定)
- 新しい色を足したくなったら、まず「意味色かアクセントで表現できないか」を検討する。増やす場合は本書を更新してから実装する
